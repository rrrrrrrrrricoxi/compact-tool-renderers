## Async control hardening (v1.17.2)

The existing tool/report Options callbacks intentionally fire-and-forget `display.control()`. A rejected native selection previously escaped that boundary as an **unhandled promise rejection** (reproduced against v1.17.1 in an isolated installed SDK session, not observed as a live terminal crash). Only this owned UI-action boundary now catches failures: active errors receive a bounded error notification through a host method captured while the context is valid. If notification itself throws or rejects, one bounded console diagnostic reports both failures; no recursive dialog is opened. Disposed/changed-epoch interactions cannot notify a successor. Awaited `/blocks` command errors still propagate to Pi's native handler; rendering exceptions are not suppressed.

A second reproduced regression allowed a delayed Jump selection to navigate a newly selected pane. Jump now checks the runtime epoch and the same open pane's cached navigation-array identity before applying a selection; changed anchors are conservatively canceled. There is no history traversal or new control framework.

`control-lifecycle.test.mjs` exercises actual installed SDK bindings and 20 real `session.reload()` cycles with pending dialog resolution/rejection, revoked contexts, inactive old controls, real temporary-file persistence failure, throwing/rejecting feedback, native awaited-command errors, immutable in-memory history and zero input/agent/model calls. Its dialogs and pane-selection state are deterministic host test fixtures, not live terminal interaction. `reload-lifecycle.test.mjs` now separately executes 20 real reload cycles, alternating Quiet/Compact with retained actual native thinking/report/question components, redraw during resource loading, Dark/Light/System palettes and native thinking visibility. The existing suites retain native tool/card mouse, expansion, narrow-layout, cache, branch and ownership coverage. `npm test` runs all 12 previous suites plus the new control suite.

Backup of the entire pre-pass v1.17.1 package: `~/.pi/agent/backups/renderer-hardening-20261011.tCqQqN/`. No master reload, networking, installation, real model request, core/other-extension/settings/auth modification or private fixture copying was performed. The authorized existing-session replay was rerun read-only. This is narrowly bounded hardening, not a guarantee against all future host/rendering/terminal failures.

## Subagent results and questions: shared panes (v1.17.0)

All presentation lives in this existing package. Recognized child results and `subagent_question` records stay separate from routine tool groups and use the **same GroupPane** frame, status palette, adaptive height and fixed controls as tool/thinking details.

- **Quiet collapsed:** one content row with disclosure, recorded status/name/time and an extractive report excerpt. Questions instead have a conspicuous **? Question** label and an excerpt of their actual question; missing elapsed time is not invented. Extraction is bounded to 8 KiB and does not request a model. Failures/cancellation prioritize their recorded reason. Native shell height is two rows: one separator plus one content row.
- **Compact collapsed:** at most two content rows plus the separator, with no duplicated excerpt or padded native box.
- **Click / Ctrl+O in Quiet or Compact:** readable Markdown inside the existing bounded frame. The 45% terminal-relative cap, numeric maximum, frame and body-background preferences are shared. Wheel scrolling is contained; the fixed footer provides scroll/page controls, Raw/Readable, Close and Options where space permits. There are no invented tool-call navigation anchors. Header clicks and footer Close use public native expansion; body selection and drag remain available.
- **Raw:** complete original message content and all recorded JSON metadata, including follow-up source, stats, task/session fields and unknown keys. No metadata dump appears in the default readable view. Original spacing/graphemes remain recoverable; terminal control bytes and glyphs unpaintable at one-column widths are escaped rather than executed or clipped.
- **Explicit `/blocks expanded`:** unbounded readable or Raw escape hatch. Its wheel events scroll the conversation rather than an internal zero-overflow viewport. The native expansion flag remains authoritative, so an individual header can still collapse/reopen the card.
- **Questions:** full question text is readable on expansion, with the same Raw access. Question records are not merged, dismissed, marked answered, or reclassified as completed. Parent-directed `ask_question` delivery, waiting/process state and reply routing are unchanged. This is not a new reply tool or a human-popup bypass.
- Running/status notices, action-required *result* payloads, attachments and malformed/unsupported shapes delegate to native presentation. Unsupported versions/non-TUI remain native, including existing native limitations.

The shared six-item Options menu follows the **last interacted report/question or tool pane**, never whichever rendered last. Its first entry and status are contextual; report/question panes hide call navigation. `/blocks scroll …`, `raw`, `close` and ordinary `open` act on the selected details; `/blocks open latest` explicitly selects tools. Thinking retains its own controls. A report's Close affects only that card, not global tool/skill expansion. Public footer-status invalidation requests command repaint with an empty extension-owned key; wheel/mouse repaint uses native `render:true`, without history traversal or all-card expansion resets.

Pi 1.1.0 has no public next-message-renderer resolver and uses first matching registration, so a later duplicate cannot override Amos. This package owns a version/shape/TUI-gated adapter on exported CustomMessageComponent rebuild/render, temporarily substitutes only recognized presentation, and restores the original renderer in finally. One symbol-owned per-card GroupPane survives native rebuilds; no registry/root traversal is added. Owned cleanup and stale target guards preserve fallback. Body layout is cached by width, view, content revision, style and theme; wheel and height-only resize reuse it. Initial large Markdown/Raw wrapping is not virtualized.

## Adaptive grouped action viewport and controls (v1.11.0)

Click a quiet grouped summary in fullscreen mode to open **all recorded actions in that run**, in invocation order, inside one bounded inline viewport. The representative card is only the display location; it no longer expands just its own output. Each operation has an ordinal/count, tool name, category and status, with a themed heading and a continuous border attaching it to its own body. Scalar arguments stay on one line (`path: …`, `timeout: 10`); scripts retain syntax highlighting, nested timings are rounded, and codemode output is separately normalized for readability. The status-tinted action background now fills its entire padded body, including blank and wrapped rows. Foreground syntax/diff/error colors and explicit nested renderer backgrounds remain intact: background-only resets (SGR 0/49, including combined SGR parameters and semicolon/colon extended colors) restore the containing card background. A persistent outer frame encloses the expanded summary, viewport and footer even when an action heading has scrolled away. Collapsed summaries remain minimal. Controls are in a fixed footer after the content, not in the summary heading.

- Default pane height is **adaptive**: up to 45% of the current terminal/tmux pane's rows, reserving eight rows for summary/footer/separator/editor chrome, with a minimum of one body row. Dimensions are read from `process.stdout.rows` on each render (24-row fallback outside a TTY). `/blocks height auto` restores adaptive sizing; `/blocks height 1..200` sets a smaller maximum, still capped by the terminal size. These preferences persist immediately without reloading. Narrow/resize rendering stays width-bounded; a one-column interior omits the scrollbar. At widths 1–2, framing degrades to a clipped chrome corner and prioritizes body text; from width 3 both outer sides remain visible. The scrollbar is inside the right frame.
- Mouse wheel scrolls inside the pane and is consumed even at its edges (no accidental transcript scrolling). Click the heading again to close. Body clicks do not collapse it. Primary drags remain available for transcript selection. The painted scrollbar indicates position; it is not a draggable control.
- **Discoverable controls:** bare `/blocks` or `/blocks menu` opens a six-item native root menu: **Tools…**, **Thinking…**, **Appearance…**, **Display mode…**, **Help & status…**, **Done**. Short current-state labels replace the long flat list. Tools/Thinking contain only relevant open/close, navigation and nested scrolling choices; unavailable panes show a brief explanation and Back, not repeated disabled rows. Appearance contains adaptive height, frame/background toggles and readable/raw tool output when a tool pane is open. Back returns to the parent page; Escape from a submenu returns to the root, and Escape at the root exits without writes or reload. Choices apply immediately and remain in the relevant submenu; display-mode reload exits all menus safely. `/blocks help` lists all typed options; argument completions remain available. Template compaction and thinking topic previews follow display mode, not independent toggles; Pi's global tool/skill expansion is coupled. Native selection owns keyboard focus only while explicitly open; the extension installs no input listener or raw-key interceptor.
- **Visual toggles:** `/blocks frame on|off` and `/blocks body-highlight on|off` default on, persist in the package-owned preference file while preserving unknown fields, and apply immediately without reload. These control the enclosing frame and action-body tint independently; intentional nested/stock renderer backgrounds remain even when body highlight is off.
- **Recorded-call navigation:** fixed `[← Previous] [Next →] [Jump…]` footer controls and `/blocks previous|next|jump [ordinal]` navigate cached top-level call headings in invocation order. Previous first returns to the current heading when mid-output, then to the preceding call. Jump opens a native selection list showing recorded tool/category/target/status. The summary begins with the current ordinal/tool so it remains useful at narrow widths. If the last call is shorter than the viewport, native scroll clamping keeps it visible while the indicator honestly names the call at the viewport's top. No output parsing, inferred nested calls, or body relayout on scrolling. Narrow footers use compact arrows/menu; `/blocks` remains the keyboard route.
- Keyboard/regular-mode path: `/blocks open` (or `/blocks open latest`), `/blocks scroll up|down|page-up|page-down|home|end`, `/blocks close`. Commands address the last clicked/opened/native-expanded pane and notify when none is active. `/blocks close` also uses Pi's public global tool/skill collapse API, so panes opened through Ctrl+O actually close. **No keyboard focus capture or raw-key interception**: editor typing, IME and global shortcuts remain owned by Pi. These commands do not reload or request a model/tool call.
- **Bounded scrolling is the default expanded view in quiet mode**, whether opened by click or Ctrl+O. Routine calls remain one grouped pane; exceptional error/cancelled/started/image calls retain their own rows and bounded detail panes. Grey strips stay collapsed until opened. `/blocks raw` toggles recorded JSON/text inside the same bounded pane. `/blocks expanded` explicitly selects unbounded original tool details; compact mode retains its original per-call behavior.
- Nested codemode headings use recorded `details.calls` or the result message's `nestedCalls` metadata, never source-code inference. Metadata records invocation order, arguments/status/duration/error, not nested outputs. Script `text()` output remains separately labeled, never guessed as a result of a particular nested operation. Missing arguments and incomplete records are explicitly labeled.
- Small complete JSON output is parsed with `JSON.parse` only (no eval) and rendered as labeled values, turning string-leaf escaped newlines into readable multiline text. Plain/malformed/oversized output remains text. Original key/value structure and raw details remain available; normalized layout is a view, not a new result.
- Implementation uses public tool-renderer components and native `ScrollView` scroll/clamp state. Pi **1.1.0**'s tool shell and its `MouseRegion` are opaque layout leaves and do not forward layout constraints. A small version-gated **local bounded paint/mouse adapter** therefore clips the viewport and paints its scrollbar; no core/prototype/root patch. Unsupported Pi versions fall back to the original compact/native per-call rendering rather than installing this adapter.
- Branch/session/reload rebuild drops pane state and abandoned references. Only display references to existing arguments/results are retained; history, execution, model context and original images are untouched. Images and exceptional error/cancelled/started rows remain independently visible as before.
- Body layout and recorded-call anchors are cached by content revision, width, raw mode, visual settings and resolved theme palette. Scrolling or height-only resizing reuses it; content, width and theme changes rebuild it. Limits: exceptionally large runs still cost wrapping/highlighting time on the initial build; there is no virtualization or new dependency. The terminal-height cap is a conservative heuristic, not measurement of Pi's editor/transcript split. This is not a live terminal acceptance check.

## Collapsed thinking topic previews (v1.8.0)

Thinking defaults to collapsed through Pi's native `hideThinkingBlock: true` setting. Quiet/compact modes replace each hidden thinking run's generic label with one muted, width-bounded topic row, for example:

```text
Thinking · Considering request behavior · Ctrl+T to expand
```

- Preview uses up to two Markdown headings, or a short first-line excerpt when no headings are available. It is an **extractive topic preview, not a complete semantic summary**. Only the first 8 KiB of each run is considered; there are no extra model calls, network requests, logs, or timers.
- Native **Ctrl+T** and clicking a thinking row retain full expand/collapse behavior. Expanded thinking is the original Markdown. Ordinary assistant prose, failures, tool execution, stored messages and model context are unchanged.
- Streaming updates refresh the topic; narrow widths stay one row. Adjacent thinking blocks share a preview; thinking separated by prose has distinct previews. Theme changes and Unicode width are supported.
- Pi does not expose a per-thinking-block renderer. This is a **version-gated Pi 1.1.0 compatibility adapter** around the exported `AssistantMessageComponent.updateContent` method, replacing only native hidden `Text` children. No installed Pi files or terminal layout are patched. It installs only in TUI mode, restores its owned method on shutdown/reload, and fails back to stock rendering on an unsupported version or unexpected shape.
- `/blocks expanded` bypasses topic previews; thinking visibility remains independently controlled by native Ctrl+T or Settings → Hide thinking. Ctrl+T persists Pi's visibility preference. The adapter does not repeatedly force-collapse thinking after a deliberate expansion.
- Disabling this extension leaves the native `hideThinkingBlock` preference intact; change it in `/settings` or with Ctrl+T if desired.

## Quiet grouped display (v1.7.0, default)

Repeated tool-only activity is folded into **one muted summary row per run**, without full-width success/pending backgrounds or repeated expansion hints. For example:

```text
Tools · 7 calls · codemode ×4, bash ×2, read
```

- Runs can span tool-only assistant messages, including thinking-only messages. Visible assistant prose, human/user messages, displayed custom reports and compaction/branch summaries separate runs.
- During execution, the summary reports unsettled/running calls. Failures remain separate, conspicuous compact error blocks (including nonzero shell exits and failed nested codemode calls). Cancellations, asynchronous `started` acknowledgements and image-bearing calls retain individual rows.
- Summary counts refer to top-level tool calls. Codemode's nested calls remain inside that call's full details, not double-counted.
- Truncation and saved-output notices remain visible. Arguments, paths, code, results and diffs are available through **Ctrl+O** or a summary click, both opening the bounded whole-run action viewport above. Use `/blocks raw` for recorded text within the pane, or `/blocks expanded` for explicit unbounded original rendering.
- Hidden members return zero lines from both renderer slots. Pi's public self-render shell then suppresses their separator as well—no blank gap per hidden call.
- Branch state is rebuilt from `getBranch()`; lightweight lifecycle observers track current activity and ignore nested execution events. IDs, names, statuses/counts, redraw callbacks and display-only references to recorded arguments/results are retained, without rewriting or duplicating transcript entries. No timers, polling, root inspection, transcript mutation, or core-file patches.
- This is display grouping, not an execution batch, safety classification, or reduction in actual model/tool calls. Ordinary assistant prose, inline images and model context remain unchanged. Hidden thinking labels use the topic previews described above.

`/blocks compact` restores the prior colored two-row-per-call display. `/blocks quiet` returns to grouping. Both commands require idle/no tracked children because mode changes reload the display runtime.

## Per-call compact and expanded renderers

- Covers every tool block through a catch-all renderer resolver, including unknown/future tool names. Specialized summaries cover codemode, write, edit, bash, PowerShell, web search/fetch, and file operations. MCP and other extension tools use a compact generic fallback. Execution and registration of tools are unchanged.
- In **compact** mode, collapsed tool blocks have one title/call row and one result/status row, with original-theme colored backgrounds but no vertical padding. Quiet mode folds routine calls as described above.
- Codemode status: call count, up to two distinct tool names, wall time when provided, failure/cancellation counts.
- Web search: short query title, result count, duration, and details hint; no raw JSON while collapsed. Web fetch: hostname/path title, status, and output count; no page body while collapsed.
- Read/grep/find/ls: category and target; result counts/status only. Unknown tools hide raw arguments and output while collapsed. Structured errors/cancellation and asynchronous `started` acknowledgements are explicitly labeled.
- In compact/expanded modes, expansion delegates to the registered renderer when available; otherwise it displays the complete recorded arguments and text. Quiet-mode bounded cards use concise recorded arguments and registered result renderers, retaining file/diff highlighting. No research guardrails or MCP execution paths are modified.

Conservative local heuristics choose the category; unknown commands get a generic label. Historical intent labels remain readable but are no longer requested.

- Errors: a short error excerpt when available, plus nonzero exit status for bash; full details on expansion.
- Full script, file contents, commands, nested arguments, output, images, and saved-output paths remain available on expansion (default shortcut **Ctrl+O**). Stock renderers retain file/diff highlighting; bash has a simple custom heading.
- Stock components are recreated on expansion to avoid incompatible collapsed-component caches. The stock bash live clock is stopped when collapsing.
- Output is hidden only in the terminal preview; model context, session records, execution, permissions, and tools are unchanged. Existing history is not rewritten.
- Scope boundary: tool resolvers plus a display-only user Markdown transformer cover tool blocks and recognized prompt-template messages; v1.15.0 adds the narrowly scoped completed-subagent custom-message adapter described above. Ordinary user text, assistant prose, expanded thinking, other custom messages (including running status and unsupported question shapes), widgets, dialogs, notifications, and independently rendered inline images are unchanged. Hidden thinking labels are compacted as described above. Inline image previews use Pi's separate `terminal.showImages` setting, which this extension does not change. Image metadata appears in the compact status; original image results remain available.
- No Ascend-specific integration and no ccc installation.
